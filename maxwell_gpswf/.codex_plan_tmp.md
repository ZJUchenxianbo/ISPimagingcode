# Remove the ideal data mode

## Goal

- Remove `ideal` as a public or experimental data mode from the Maxwell GPSWF subproject.
- Make all numerical experiments use the finite-direction mock workflow only.
- Keep low-level admissible direction-pair geometry utilities when they are required internally by forward solvers; these utilities will no longer constitute a selectable experiment mode.

## Current scope of the ideal mode

The ideal branch currently appears in:

- `ExperimentConfig.data_mode` and `maxwell_gpswf/main.py --data-mode`;
- standalone CLIs for `exp1`--`exp4` and legacy `figure4`--`figure7` scripts;
- current and legacy experiment conditionals;
- `generate_polarimetric_data_nodes()` and `generate_data_nodes()`;
- `maxwell_gpswf/README.md`, `output_guide.tex`, and `maxwell_gpswf/AGENTS.md`.

Removing only the TeX text would leave the mode executable, so the code and documentation must be changed together.

## Planned code changes

1. Remove `data_mode` from `ExperimentConfig` and remove `--data-mode` from the main CLI.
2. Remove `--data-mode` from standalone experiment CLIs.
3. Make `generate_polarimetric_data_nodes()` and `generate_data_nodes()` mock-only:
   - remove their `data_mode` arguments;
   - remove their ideal branches;
   - retain nearest-neighbor matching and mock-distance diagnostics;
   - continue writing `data_mode="mock"` into diagnostic metadata for compatibility with existing CSV analysis.
4. Update `exp1`--`exp4` to call the mock-only quadrature interface and record `data_mode="mock"` explicitly.
5. Simplify legacy `figure1`--`figure7` scripts to their existing mock branches and remove ideal-specific conditionals.
6. Keep `admissible_farfield_pairs_from_nodes()` and related geometry helpers because forward data generators may use them internally when explicit direction pairs are absent; they will not be exposed as a data mode.

## Documentation changes

1. Remove ideal-mode commands and descriptions from `maxwell_gpswf/README.md`.
2. Remove the ideal-mode paragraph and command option from `output_guide.tex`.
3. Update `maxwell_gpswf/AGENTS.md` so future changes treat finite-direction mock data as the only experiment workflow.
4. Keep the distinction between target quadrature nodes and matched measured Fourier nodes, because it remains essential to the numerical method.

## Validation

1. Search the subproject for remaining user-facing `ideal` and `data_mode` references.
2. Run `.venv/bin/python -m py_compile` on all Python files in `maxwell_gpswf`.
3. Check `main.py --help` and standalone `exp1`--`exp4 --help` output to confirm that `--data-mode` is absent.
4. Run the current experiments in quick mode through `main.py --mode all --quick`.
5. Compile `output_guide.tex` with a temporary XeLaTeX wrapper and inspect the log.
6. Delete smoke-test outputs, TeX build files, and this plan file.

## Out of scope

- Do not change the number of Lebedev directions, polarimetric configurations, quadrature nodes, noise levels, or modal truncation parameters.
- Do not change the forward far-field formulas or reconstruction algorithms.
- Do not delete admissible direction-pair helpers that are still used internally outside the removed mode switch.
